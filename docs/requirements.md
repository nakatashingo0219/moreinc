# 花屋向け 在庫管理システム 要件定義書（ドラフト v0.1）

| 項目 | 内容 |
|---|---|
| 対象 | 株式会社きむらフローリスト（店舗型の生花店） |
| 文書の目的 | 開発者へ渡す前提で、作るもの・作らないものを決める |
| 作成日 | 2026-11-09 |
| 状態 | ドラフト（「11. 確認事項」への回答を受けて確定させる） |

---

## 1. 背景と課題

- 在庫は数百種類あるが、**「何が・どこに・何個あるか」が把握できていない**。
- POSレジとして **Airレジ** を利用中。売上計算はタブレットで行えているが、商品・在庫の登録・更新は件数が多く、手入力が負担になっている。
- **年末に棚卸し**を予定しており、それ以降はシステムで在庫を管理したい。
- Airレジのバックオフィスには **CSVによる商品の一括登録** 機能があるため、このシステムからCSVを出力して取り込めば、入力の手間を減らせる。

## 2. 目的とゴール

| # | ゴール | 測り方（目安） |
|---|---|---|
| G1 | 主要商品の在庫数と保管場所を、誰でもすぐ確認できる | 商品を探して在庫数が分かるまで10秒以内 |
| G2 | 入荷・販売・廃棄の記録を短時間でつけられる | 1件の記録が3タップ以内 |
| G3 | Airレジへの商品登録を、手入力からCSVの一括取り込みに切り替える | Airレジ側で手入力する件数が0件 |
| G4 | 年末の棚卸しをシステムで行える | 棚卸しの結果がそのまま在庫数になる |
| G5 | （任意）売れ筋商品・季節商品の動きを把握し、仕入れや販促に使う | ダッシュボードで週1回は確認される |

## 3. 進め方（段階導入）

一度にすべてを登録するのではなく、**売れ筋の約20品目から始めて少しずつ増やす**。

| フェーズ | 時期（目安） | 内容 |
|---|---|---|
| **Phase 1（MVP）** | 年末の棚卸しまでに | 商品マスタ、保管場所、在庫の確認、入荷・販売・廃棄の記録、棚卸し、Airレジ用のCSV出力。対象は主要20品目 |
| **Phase 2** | 年明け〜 | Airレジの売上CSVを取り込んで在庫を自動で減らす、在庫が少ない商品の通知、品目の追加 |
| **Phase 3** | 運用が安定したら | 売れ筋・季節商品のダッシュボードと通知（マーケティングへの活用） |

> 品目を増やすのはシステムの改修ではなく、**画面からの登録またはCSVの取り込みだけで行える**ようにする。

## 4. 利用者

| 利用者 | 主な操作 | 端末 |
|---|---|---|
| 店舗スタッフ | 在庫の確認、入荷・販売・廃棄の記録、棚卸しの入力 | タブレット（店頭）、スマートフォン |
| 店長・管理者 | 商品の登録、CSVの入出力、ダッシュボードの確認、設定 | PC、タブレット |

- ITに詳しくない人が、**説明書なしで使える**ことを前提にする。
- 同時に使う人数は数名程度を想定する。

## 5. 機能要件

優先度：**必須**＝Phase 1、**推奨**＝Phase 2、**任意**＝Phase 3

### 5.1 商品マスタ管理（必須）

| ID | 要件 |
|---|---|
| F-01 | 商品の登録・編集・削除（使わなくなった商品は削除ではなく「販売停止」にして履歴を残す） |
| F-02 | 管理する項目：商品コード、商品名、カテゴリ、単位（本／束／鉢／個）、販売価格、仕入れ価格（任意）、税区分、季節タグ、日持ちの目安日数、発注点（これを下回ったら通知する数）、Airレジの商品ID（連携用）、写真（任意）、メモ |
| F-03 | 「管理対象」フラグをつけ、Phase 1は主要20品目だけを画面に表示する。フラグを切り替えるだけで対象を増やせる |
| F-04 | 商品マスタをCSVで一括登録・一括更新できる（数百品目を後から追加するため） |
| F-05 | カテゴリの例：切り花／枝物／鉢物・観葉植物／プリザーブド・ドライ／資材（花器・ラッピング・リボン等）／ギフト・アレンジ |

### 5.2 保管場所の管理（必須）

| ID | 要件 |
|---|---|
| F-10 | 保管場所を登録できる（例：店頭、フラワーキーパー（冷蔵ケース）、バックヤード、倉庫、資材棚） |
| F-11 | 1つの商品を複数の場所に置ける。在庫は「商品 × 場所」ごとに持つ |
| F-12 | 場所の移動（例：バックヤード → 店頭）を記録できる |

### 5.3 在庫の確認（必須）

| ID | 要件 |
|---|---|
| F-20 | 在庫一覧：商品名・写真・合計の在庫数・場所ごとの内訳を表示する |
| F-21 | 商品名（ひらがな・カタカナどちらでも）、カテゴリ、場所で絞り込める |
| F-22 | 在庫が発注点を下回った商品を色分けして目立たせる |
| F-23 | 切り花は入荷日を記録し、日持ちの目安を過ぎそうな在庫を「早めに売りたい」として表示する |

### 5.4 入出庫の記録（必須）

| ID | 要件 |
|---|---|
| F-30 | 記録の種類：**入荷**／**販売**／**廃棄（ロス）**／**移動**／**数の修正** |
| F-31 | 商品を選び、「＋」「−」ボタンかテンキーで数を入れて確定する。最短3タップで終わる |
| F-32 | 廃棄のときは理由を選べる（しおれ・傷み・破損・その他） |
| F-33 | すべての記録に日時と記録した人を残し、履歴として見られる。間違えた記録は取り消せる |

### 5.5 棚卸し（必須）

| ID | 要件 |
|---|---|
| F-40 | 棚卸しモード：場所ごとに商品のリストを出し、実際に数えた数を入力していく |
| F-41 | システム上の数と実際の数の差を一覧で表示し、確定するとその数で在庫を上書きする |
| F-42 | 棚卸しの結果をCSVで出力できる（会計・記録用） |
| F-43 | 途中で保存して後から続きを入力できる |

### 5.6 Airレジとの連携（CSV）

| ID | 優先度 | 要件 |
|---|---|---|
| F-50 | 必須 | **Airレジの商品一括登録用CSVを出力する**。出力するのは「新しく追加した商品」「変更した商品」「全件」から選べる |
| F-51 | 必須 | CSVの列の並びや文字コードは、Airレジのバックオフィスから実際に出力したCSVに合わせる。列の対応は設定ファイルで変えられるようにし、Airレジ側の仕様が変わってもプログラムを直さずに済むようにする |
| F-52 | 推奨 | **Airレジの売上データ（商品別）のCSVを取り込み**、売れた数だけ在庫を自動で減らす。同じファイルを2回取り込んでも二重に減らないようにする |
| F-53 | 推奨 | 取り込んだときに、Airレジにはあるがこのシステムにない商品を一覧で表示する（品目追加の候補になる） |

> Airレジとのやりとりは **CSVファイルの手動の入出力** とする。API連携は対象外（Airレジの外部API公開状況に左右されるため、将来の検討課題とする）。

### 5.7 通知（推奨）

| ID | 要件 |
|---|---|
| F-60 | 在庫が発注点を下回ったら、トップ画面に通知を出す |
| F-61 | 日持ちの目安が近い切り花を通知する |
| F-62 | （任意）通知をメールやLINEに送る。まずは画面内の通知だけでよい |

### 5.8 ダッシュボード（売れ筋・季節商品の分析）（任意：Phase 3）

在庫管理のデータを、仕入れと販促（マーケティング）にも使えるようにする。Airレジの売上CSV（F-52）を取り込んでいることが前提。

| ID | 要件 |
|---|---|
| F-70 | **売れ筋ランキング**：今週／今月／前年同月の売上数・売上金額の上位10品目 |
| F-71 | **伸びている商品**：前の週・前の月と比べて販売数が大きく増えた商品を表示する |
| F-72 | **季節イベントの事前通知**：イベントの2〜4週間前に、昨年同じ時期に売れた商品と数を表示し、仕入れの目安を示す |
| F-73 | **在庫と売れ行きの組み合わせ**：「よく売れているのに在庫が少ない」（仕入れを増やす）、「在庫が多いのに売れていない」（店頭で目立たせる・セットにする）を表示する |
| F-74 | **廃棄（ロス）の集計**：品目ごとの廃棄の数・金額と廃棄率。仕入れ量を見直す材料にする |
| F-75 | グラフは折れ線（推移）と棒（ランキング）を基本とし、スマートフォンでも読める大きさにする |

季節イベントの初期設定例（店舗ごとに編集できる）：

| 時期 | イベント | 動きやすい商品の例 |
|---|---|---|
| 1月 | 正月（年末から） | 松・千両・葉牡丹・正月アレンジ |
| 2月 | バレンタイン | バラ・ミニブーケ |
| 3月 | 卒業式・送別会・春の彼岸 | 花束・スイートピー・仏花 |
| 4月 | 入学式・歓送迎会 | 花束・スタンド花 |
| 5月 | 母の日 | カーネーション・鉢物 |
| 6月 | 父の日 | ひまわり・黄色系の花 |
| 8月 | お盆 | 仏花・菊・ほおずき |
| 9月 | 敬老の日・秋の彼岸 | 鉢物・仏花 |
| 10月 | ハロウィン | 実もの・オレンジ系 |
| 12月 | クリスマス・年末 | ポインセチア・シクラメン・リース |

> 傾向を正しく出すには最低でも1年分の売上データが必要。Airレジに過去の売上が残っていれば、最初にまとめて取り込む。

| 3 | 在庫一覧 | 検索、絞り込み、商品ごとの在庫数と場所 |
| 4 | 商品詳細 | 商品情報、場所ごとの在庫、入出庫の履歴 |

| 7 | 商品マスタ | 商品の登録・編集、CSVの取り込み |

## 7. 使いやすさの要件（最優先）

- タブレットを縦にも横にも持てる。ボタンは指で押しやすい大きさ（目安：縦横44px以上）。
- 1画面に表示する操作は少なくし、よく使う操作はホームから1タップで開ける。
- 文字は大きめにし、専門用語を使わない（「SKU」ではなく「商品」、「入庫」ではなく「入荷」）。
- 商品は写真つきで表示し、名前を読まなくても選べるようにする。
- 間違えても取り消せる。確定前に「○○を10本 入荷します」と確認を出す。
- 水や手袋で操作しにくい作業場を考え、入力欄は少なくする。

## 8. 非機能要件

| 項目 | 要件 |
|---|---|
| 利用環境 | ブラウザで使うWebアプリ。iPad／Androidタブレット、スマートフォン、PCのChrome・Safariの最新版で動く |
| 性能 | 在庫一覧（品目数1,000まで）が2秒以内に表示される |
| データ量 | 品目：最大1,000、入出庫の記録：年間数万件を想定 |
| バックアップ | データを毎日自動でバックアップし、少なくとも30日分を残す |
| セキュリティ | 通信はHTTPS。ログインが必要。管理者だけが商品マスタ・設定・CSVの入出力をできる |
| 個人情報 | **お客様の個人情報は扱わない**。Airレジの売上CSVを取り込む際も、商品・数量・金額・日時だけを使い、それ以外の列は保存しない |
| 保守 | 開発者以外でも設定（場所・カテゴリ・季節イベント・CSVの列の対応）を画面から変えられる |

## 9. 技術方針（開発者向けの推奨）

| 項目 | 推奨 | 理由 |
|---|---|---|
| 言語 | Python 3.12 以上 | ご希望どおり。開発者が多く、引き継ぎやすい |
| フレームワーク | Django | ログイン・管理画面・データベース操作が最初から揃っており、小規模な業務システムを少ないコードで作れる |
| データベース | SQLite（はじめ）→ 必要になればPostgreSQL | 店舗1つ・数名の利用ならSQLiteで十分。ファイル1つなのでバックアップも簡単 |
| 画面 | Djangoのテンプレート ＋ 軽いJavaScript（htmx等） | アプリのインストールが不要で、タブレットのブラウザでそのまま使える |
| グラフ | Chart.js | ダッシュボード用。導入が簡単 |
| 公開方法 | クラウド（例：Render、Railway、さくらのVPS等）で月数千円程度 | 店舗・自宅どこからでも見られる。店舗PCでの運用も可能だが、バックアップと外からの利用を考えるとクラウドを推奨 |

**データの基本構造（参考）**

```
商品（Product）       ：商品コード, 商品名, カテゴリ, 単位, 販売価格, 仕入価格, 税区分,
                        季節タグ, 日持ち日数, 発注点, AirレジID, 管理対象フラグ, 販売停止フラグ
保管場所（Location）  ：名前, 並び順
在庫（Stock）         ：商品, 保管場所, 数量                     ※商品×場所で1行
入出庫履歴（Movement）：日時, 商品, 場所, 種類(入荷/販売/廃棄/移動/修正), 数量, 理由, 記録者
棚卸し（Stocktake）   ：実施日, 状態(入力中/確定), 明細(商品, 場所, システム数, 実数)
売上取込（SalesImport）：取込日時, ファイルの識別値(二重取り込み防止), 期間
季節イベント（Event） ：名前, 開始日, 終了日, 関連カテゴリ・商品
```

## 10. 対象外（今回は作らないもの）

- Airレジとの自動連携（API連携）
- 発注書の作成・仕入先への自動発注
- 会計・経理の機能（仕訳、請求書など）
- お客様の管理（顧客台帳、会員、ポイント）
- 複数店舗の管理（必要になれば将来検討）
- ネットショップとの在庫連携

## 11. 確認事項（お客様・開発者に確認したいこと）

| # | 確認したいこと | なぜ必要か |
|---|---|---|
| Q1 | 主要20品目のリスト（商品名・単位・価格） | Phase 1の初期データになる |
| Q2 | Airレジのバックオフィスから出力した「商品のCSV」と「売上のCSV」のサンプル（各1つ） | CSVの形式を正確に合わせるため。**最重要** |
| Q3 | 保管場所の一覧（店頭・冷蔵ケース・バックヤード等） | 場所の初期設定 |
| Q4 | 切り花は「本」で数えるか「束」で数えるか。束を本にばらして売ることはあるか | 単位の換算が必要かどうかが決まる |
| Q5 | アレンジメントや花束（複数の花を組み合わせた商品）が売れたとき、使った花の在庫も減らしたいか | 必要なら「レシピ（構成）」機能を追加する。最初は対象外とし、廃棄・修正で調整する案を推奨 |
| Q6 | 使う端末（タブレットの機種、台数）と店内のWi-Fiの有無 | 画面設計と公開方法の判断 |
| Q7 | 使う人数と、操作した人を記録する必要があるか | ログイン方式（共通パスワードか個人PINか） |
| Q8 | 年末の棚卸しの日程 | Phase 1の締め切り |
| Q9 | 月々の運用費（サーバー代）の上限 | 公開方法の決定 |
| Q10 | 保守（不具合対応・機能追加）を誰が担当するか | 引き継ぎ資料の範囲 |
