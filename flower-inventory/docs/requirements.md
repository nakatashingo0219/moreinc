# お花在庫管理システム（株式会社きむらフローリスト） 要件定義書（ドラフト v0.4）

| 項目 | 内容 |
|---|---|
| 対象 | 株式会社きむらフローリスト（店舗型の生花店） |
| 文書の目的 | 開発者へ渡す前提で、作るもの・作らないものを決める |
| 作成日 | 2026-11-09 |
| 状態 | ドラフト v0.4（数量のみの管理に絞る。アレンジ・花束は保留。主要20品目は観葉植物などのサンプル） |

---

## 1. 背景と課題

- 在庫は数百種類あるが、**「何が・どこに・何個あるか」が把握できていない**。
- POSレジとして **Airレジ** を利用中。売上計算はタブレットで行えているが、商品・在庫の登録・更新は件数が多く、手入力が負担になっている。
- **年末に棚卸し**を予定しており、それ以降はシステムで在庫を管理したい。
- Airレジのバックオフィスには **在庫数をCSVで一括編集する機能**（在庫一括編集CSV）があるため、このシステムからCSVを出力して取り込めば、Airレジ側の在庫数を1件ずつ手入力しなくて済む。

## 2. 目的とゴール

| # | ゴール | 測り方（目安） |
|---|---|---|
| G1 | 主要商品の在庫数と保管場所を、誰でもすぐ確認できる | 商品を探して在庫数が分かるまで10秒以内 |
| G2 | 入荷・販売・廃棄の記録を短時間でつけられる | 1件の記録が3タップ以内 |
| G3 | Airレジの在庫数の更新を、手入力からCSVの一括取り込みに切り替える | Airレジ側で在庫数を手入力する件数が0件 |
| G4 | 年末の棚卸しをシステムで行える | 棚卸しの結果がそのまま在庫数になる |
| G5 | （任意）売れ筋商品・季節商品の動きを把握し、仕入れや販促に使う | ダッシュボードで週1回は確認される |

## 3. 進め方（段階導入）

一度にすべてを登録するのではなく、**売れ筋の約20品目から始めて少しずつ増やす**。

| フェーズ | 時期（目安） | 内容 |
|---|---|---|
| **Phase 1（MVP）** | 年末の棚卸しまでに | 商品マスタ、保管場所、在庫の確認、入荷・廃棄の記録、棚卸し、**Airレジとの在庫の同期（在庫一括編集CSVの取り込み・出力）**。**数量だけを管理し、価格は扱わない**。対象は主要20品目（「付録A」のサンプル。観葉植物など数えやすいもの） |
| **Phase 2** | 年明け〜 | 通知の強化（メール等）、商品の写真、品目の追加 |
| **Phase 3** | 運用が安定したら | 売れ筋・季節商品のダッシュボードと通知（マーケティングへの活用） |
| **保留** | 時期未定 | アレンジ・花束の構成管理（5.5）。何をどれくらい使うかを把握できてから着手する。価格・金額の管理 |

> 品目を増やすのはシステムの改修ではなく、**画面からの登録またはCSVの取り込みだけで行える**ようにする。

## 4. 利用者

| 利用者 | 主な操作 | 端末 |
|---|---|---|
| 店舗スタッフ | 在庫の確認、入荷・販売・廃棄の記録、棚卸しの入力 | タブレット（店頭）、スマートフォン |
| 店長・管理者 | 商品の登録、CSVの入出力、ダッシュボードの確認、設定 | PC、タブレット |

- ITに詳しくない人が、**説明書なしで使える**ことを前提にする。
- 同時に使う人数は数名程度を想定する。

### 5.5 アレンジ・花束の構成（保留：将来対応）

> **現時点では作らない。** アレンジ・花束に何をどれくらい使っているかがまだ把握できていないため、Phase 1の商品からも外す。使う花の量が分かってから着手できるよう、考え方だけを残しておく。それまでは、アレンジ・花束に使った花は「廃棄・修正」または棚卸しで調整する。

アレンジメントや花束（複数の花や資材を組み合わせた商品）を作ったときに、**使った花・資材の在庫を減らす**。

**考え方**

- 部材（花・資材）は **アレンジ・花束を作ったとき（制作時）に減らす**。
- 作ったアレンジ・花束は「完成品」として在庫が1つ増え、Airレジで会計すると、Airレジ側で自動的に1つ減る。
- こうすると、Airレジの通常の在庫管理（会計で在庫が減る仕組み）と食い違わず、部材を二重に減らすこともない。

アレンジ・花束は、記録のしかたで2種類に分ける。

| 種類 | 例 | 記録のしかた |
|---|---|---|
| **定番品**（中身が毎回同じ） | 仏花セット、定番ミニブーケ | 商品を選んで数を入れるだけ。登録した「構成」（何を何本使うか）どおりに部材が減る |
| **オーダー品**（中身が毎回違う） | 「花束 3,000円」「おまかせアレンジ 5,000円」 | 構成がひな形として出るので、実際に使った本数を「＋」「−」で直してから確定する |

| ID | 要件 |
|---|---|
| F-34 | 商品に「構成」を登録できる。構成は「部材（花・資材）× 数量」の一覧（例：仏花セット＝商品A 2本＋商品B 1本＋商品C 3本） |
| F-35 | 商品ごとに「定番品」か「オーダー品」かを選べる（記録画面の出し方が変わるだけで、在庫の減らし方は同じ） |
| F-36 | **制作の記録**：アレンジ・花束を選び、作った数を入れると、部材が減り、完成品が増える。確定前に部材の本数を直せる（「今日はバラを1本多く使った」など） |
| F-37 | 完成品の在庫がマイナスになった場合（Airレジで会計したのに制作を記録し忘れた場合）は、「制作の記録が漏れています」とホーム画面に出し、後から制作を記録できるようにする |
| F-38 | Airレジ側では、アレンジ・花束の商品も「管理対象」をオンにしておく（運用ルール。5.7参照） |
| F-39 | 部材の在庫が足りないときは、作ることを止めずに「在庫が足りません（マイナスになります）」と警告だけ出す。差は棚卸しで直す |
| F-39a | 構成を変えても過去の記録は変わらない（記録したときの構成を残す） |

### 5.7 Airレジとの在庫の同期（CSV）（必須）

#### 5.7.1 Airレジ側の仕組み（公式FAQで確認した内容）

参照：Airレジ FAQ「在庫一括編集CSVファイルの出力項目」（2024年7月16日更新）、「CSVファイルを利用した在庫数の一括登録・編集方法」、「在庫一括編集用CSVファイルのエラー解消方法」、「在庫管理の利用方法」

- Airレジには在庫管理の機能があり、**「管理対象」をオンにした商品は、会計すると自動で在庫数が減る**（種別「販売」として記録される）。
- バックオフィスの「在庫管理」画面 →「在庫数をCSVで編集する」→「ファイルで一括編集」画面で、**編集用CSVをダウンロード → 編集 → アップロード**すると、在庫数をまとめて変更できる。パソコンのブラウザからのみ使える（Airレジのアプリでは使えない）。
- **このCSVでは商品の新規登録はできない**。商品はAirレジ側で先に登録しておく必要がある。
- アップロード時に「在庫数の編集方法」を、**「現在の在庫数に足し引きする」か「現在の在庫数を上書きする」のどちらか**から選ぶ（1ファイルにつきどちらか一方）。

**ファイルの形（FAQの画面例で確認）**：1行目が形式のバージョン（例「v200」）、2行目が項目名、3行目以降が商品ごとの行。バリエーションのない商品はバリエーションIDが「0」。バーコードは先頭に「#」が付いて出力される例がある。現在在庫数はマイナスになることがある。

**編集用CSVの列（この順番。項目名・項目数は変えてはいけない）**

| # | 項目名 | 内容 | このシステムの扱い |
|---|---|---|---|
| 1 | 商品ID | Airレジが自動で付けるID。**変更不可**・必須 | 取り込んで保存し、商品をひも付けるキーにする。出力時はそのまま戻す |
| 2 | 商品名 | 登録されている商品名 | 読み取り（初回の商品登録に使う）。出力時はそのまま戻す |
| 3 | バリエーションID | バリエーションのID。**変更不可**。バリエーションがある商品では必須 | 商品IDと組み合わせてキーにする。そのまま戻す |
| 4 | バリエーション（種別1） | 例：サイズ・色 | 読み取り・そのまま戻す |
| 5 | バリエーション（種別2） | 同上 | 読み取り・そのまま戻す |
| 6 | カテゴリー | 商品のカテゴリー | 読み取り（初回の商品登録に使う）・そのまま戻す |
| 7 | 商品コード | 設定されている場合のみ | 読み取り・そのまま戻す |
| 8 | バーコード | 設定されている場合のみ | 読み取り・そのまま戻す |
| 9 | 現在在庫数 | Airレジ上の現在の在庫数 | **取り込んで、Airレジ側の変動（会計による販売など）を計算する** |
| 10 | 更新在庫数 | **編集する列**。半角数字とマイナス記号のみ。-9,999,999〜9,999,999、更新後の在庫数もこの範囲 | **このシステムが書き込む**（足し引きする数） |
| 11 | 更新種別 | 入荷／販売／返品／破損・不良品／紛失・盗難／EC販売／棚卸し・在庫確認／その他、または空欄 | **このシステムが書き込む**（下の対応表） |
| 12 | 更新メモ | 30文字以内。機種依存文字（半角カナ、①、㈱、№、～ など）は不可 | **このシステムが書き込む**（例「入荷」「廃棄 傷み」） |
| 13 | 商品備考 | 「商品詳細」画面の備考 | そのまま戻す |

その他の注意（FAQの記載）：ファイル名は変更しない／商品ID・バリエーションIDは変更しない／項目名・項目数は変えない。更新種別・更新メモの内容はAirレジの「在庫変動履歴」（直近13か月分）に残る。

#### 5.7.2 同期のしかた（基本方針）

- **販売はAirレジが正（会計で自動的に減る）。** このシステムは、Airレジでは分からない **保管場所・入荷・廃棄・棚卸し** を受け持つ。
- Airレジへ返すのは常に **「足し引き」（差分）** にする。上書きにすると、CSVを作ってからアップロードするまでの間に売れた分が消えてしまうため。棚卸しの結果も差分に直して返す。
- 1回の同期は、店長がパソコンで次の4ステップで行う（目安：1日1回、閉店後）。

| ステップ | 操作する場所 | 内容 |
|---|---|---|
| 1 | Airレジ バックオフィス | 在庫管理 →「在庫数をCSVで編集する」→「編集用ファイル(CSV)をダウンロードする」 |
| 2 | このシステム | 「Airレジ同期」画面にそのファイルをドラッグ＆ドロップ → 前回からのAirレジ側の変動（販売など）が反映され、内容が一覧で表示される |
| 3 | このシステム | 「Airレジ用ファイルを作る」→ 未送信の入荷・廃棄などを書き込んだCSVが、**元と同じファイル名**でダウンロードされる |
| 4 | Airレジ バックオフィス | 「ファイルで一括編集」画面で **「現在の在庫数に足し引きする」を選び**、そのファイルをアップロード → 完了したらこのシステムで「アップロードした」を押す |

| ID | 優先度 | 要件 |
|---|---|---|
| F-50 | 必須 | **編集用CSVの取り込み**：Airレジからダウンロードした編集用CSVを取り込み、商品ID＋バリエーションIDで商品をひも付け、「現在在庫数」を保存する |
| F-51 | 必須 | **Airレジ側の変動の反映**：「今回の現在在庫数 −（前回の同期で確定した在庫数）」を、Airレジ側で起きた変動（主に会計による販売）として記録する。減った分は「販売」として、あらかじめ決めた場所（初期値：店頭）から減らす。増えた分は「Airレジ側の修正」として記録する |
| F-52 | 必須 | **Airレジ用CSVの出力**：取り込んだファイルと**同じファイル名・同じ列・同じ文字コード・同じ行**で出力し、変えるのは「更新在庫数」「更新種別」「更新メモ」の3列だけにする。送る変動がない行は3列とも空欄のままにする（※空欄の行がAirレジで「変更なし」と扱われることは、実ファイルで要確認。Q2） |
| F-53 | 必須 | **商品の追加**：取り込んだCSVのうち、このシステムにまだない商品を一覧で表示し、チェックを入れるだけで商品マスタに登録できる（商品名・カテゴリー・商品コード・バーコード・IDを引き継ぐ）。品目を少しずつ増やすときの基本の手順になる |
| F-54 | 必須 | **出力前のチェック**：Airレジの取り込みでエラーになる内容を事前に防ぐ。更新在庫数の範囲（-9,999,999〜9,999,999）、更新メモの30文字以内と使えない文字（機種依存文字）の除去、更新種別が8種類のどれかであること |
| F-55 | 必須 | **二重送信の防止**：出力したCSVは「アップロード待ち」として記録する。「アップロードした」を押すまで同じ変動を次のCSVに入れない。押し忘れたまま次の取り込みをした場合は、「前回のファイルをAirレジにアップロードしましたか？」と確認してから計算する |
| F-56 | 必須 | 1行に複数の変動（例：入荷10本と廃棄2本）がある場合は、合計した数（+8）を1行で送る。更新種別は最も大きい変動の種別にし、内訳を更新メモに書く（例「入荷10 廃棄2」）。※CSVは1商品1行のため |
| F-57 | 任意 | 過去のAirレジの売上データ（売上分析用のCSV）を取り込み、ダッシュボード（5.9）の分析に使う。在庫数は変えない。形式は別途確認する |

**このシステムの記録 → Airレジの「更新種別」の対応**

| このシステムの記録 | Airレジの更新種別 | 更新メモの例 |
|---|---|---|
| 入荷 | 入荷 | 入荷 |
| 廃棄（しおれ・傷み・破損） | 破損・不良品 | 廃棄 しおれ |
| （将来）制作で使った部材・完成品 | その他 | 制作 アレンジX×2 |
| Airレジを通さない販売 | 販売 | 店外販売 |
| 棚卸しの差 | 棚卸し・在庫確認 | 棚卸し 2026/12/28 |
| 数の修正 | その他 | 修正 |
| 場所の移動 | （送らない。Airレジは場所を持たないため合計は変わらない） | — |

**Airレジ側で必要な設定（運用ルール）**

- 「レジ基本設定」で「在庫管理」をオンにする。返品・伝票削除を在庫に反映するかも決めておく（反映するを推奨）。
- このシステムで管理する商品（Phase 1は付録Aの20品目）は、Airレジ側で「管理対象」をオンにする。
- レジで販売しない商品（資材など）を管理する場合も、Airレジに商品として登録しておく（このCSVでは商品を新規登録できないため）。
- Airレジ側で在庫数を直接編集するのは、なるべく避ける（行った場合も次の同期で「Airレジ側の修正」として取り込まれる）。

> Airレジとのやりとりは **CSVファイルの手動の入出力** とする。API連携は対象外（将来の検討課題）。

| F-60 | 在庫が発注点を下回ったら、トップ画面に通知を出す |
| F-61 | 日持ちの目安が近い切り花を通知する |
| F-62 | （任意）通知をメールやLINEに送る。まずは画面内の通知だけでよい |

### 5.9 ダッシュボード（売れ筋・季節商品の分析）（任意：Phase 3）

在庫管理のデータを、仕入れと販促（マーケティング）にも使えるようにする。販売数は、5.7の同期でAirレジから取り込んだ変動（F-51）を使う。毎日同期すれば日単位で集計できる。過去の分はAirレジの売上データ（F-57）で補う。

| ID | 要件 |
|---|---|
| F-70 | **売れ筋ランキング**：今週／今月／前年同月の販売数の上位10品目（金額は扱わない） |
| F-71 | **伸びている商品**：前の週・前の月と比べて販売数が大きく増えた商品を表示する |
| F-72 | **季節イベントの事前通知**：イベントの2〜4週間前に、昨年同じ時期に売れた商品と数を表示し、仕入れの目安を示す |
| F-73 | **在庫と売れ行きの組み合わせ**：「よく売れているのに在庫が少ない」（仕入れを増やす）、「在庫が多いのに売れていない」（店頭で目立たせる・セットにする）を表示する |
| F-74 | **廃棄（ロス）の集計**：品目ごとの廃棄の数と廃棄率。仕入れ量を見直す材料にする |
| F-75 | グラフは折れ線（推移）と棒（ランキング）を基本とし、スマートフォンでも読める大きさにする |

季節イベントの初期設定例（店舗ごとに編集できる）：

| 時期 | イベント | 動きやすい商品の例 |
|---|---|---|
| 1月 | 正月（年末から） | 松・千両・葉牡丹・正月アレンジ |
| 2月 | バレンタイン | バラ・ミニブーケ |
| 3月 | 卒業式・送別会・春の彼岸 | 花束・スイートピー・仏花 |
| 4月 | 入学式・歓送迎会 | 花束・スタンド花 |

| 6月 | 父の日 | ひまわり・黄色系の花 |
| 8月 | お盆 | 仏花・菊・ほおずき |

## 7. 使いやすさの要件（最優先）

- タブレットを縦にも横にも持てる。ボタンは指で押しやすい大きさ（目安：縦横44px以上）。
- 1画面に表示する操作は少なくし、よく使う操作はホームから1タップで開ける。
- 文字は大きめにし、専門用語を使わない（「SKU」ではなく「商品」、「入庫」ではなく「入荷」）。
- 商品は写真つきで表示し、名前を読まなくても選べるようにする（写真はPhase 2以降）。
- システム名は「お花在庫管理システム」。画面には株式会社きむらフローリストのロゴと会社名を表示し、色はロゴの茶色に合わせる。
- 間違えても取り消せる。確定前に「○○を10本 入荷します」と確認を出す。
- 水や手袋で操作しにくい作業場を考え、入力欄は少なくする。

| 項目 | 要件 |

## 9. 技術方針（開発者向けの推奨）

| 項目 | 推奨 | 理由 |
|---|---|---|
| 言語 | Python 3.12 以上 | ご希望どおり。開発者が多く、引き継ぎやすい |
| フレームワーク | Django | ログイン・管理画面・データベース操作が最初から揃っており、小規模な業務システムを少ないコードで作れる |
| データベース | SQLite（はじめ）→ 必要になればPostgreSQL | 店舗1つ・数名の利用ならSQLiteで十分。ファイル1つなのでバックアップも簡単 |
| 画面 | Djangoのテンプレート ＋ 軽いJavaScript（htmx等） | アプリのインストールが不要で、タブレットのブラウザでそのまま使える |
| グラフ | Chart.js | ダッシュボード用。導入が簡単 |
| 公開方法 | クラウド（例：Render、Railway、さくらのVPS等）で月数千円程度 | 店舗・自宅どこからでも見られる。店舗PCでの運用も可能だが、バックアップと外からの利用を考えるとクラウドを推奨 |

**データの基本構造（参考）**

```
商品（Product）       ：商品コード, 商品名, カテゴリ, 単位,
                        季節タグ, 日持ち日数, 発注点, AirレジID, 管理対象フラグ, 販売停止フラグ
保管場所（Location）  ：名前, 並び順
在庫（Stock）         ：商品, 保管場所, 数量                     ※商品×場所で1行

入出庫履歴（Movement）：日時, 商品, 場所, 種類(入荷/販売/廃棄/移動/修正/棚卸し/Airレジ側の変動), 数量, 理由, 記録者
棚卸し（Stocktake）   ：実施日, 状態(入力中/確定), 明細(商品, 場所, システム数, 実数)
```
